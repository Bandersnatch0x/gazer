# 0023 — roundtable 预算改为 12000ms（取代 0019 的 800ms）

日期: 2026-11-15（当日两次修订）

## 背景

0019 以 HARNESS §5 的 800ms 为权威，把 playtest 用的 20000ms 判为临时绕过，并接受“演示时模型台词出现概率下降”。2026-11-15 用真实本机端点（`http://127.0.0.1:18086/v1`，经 `/v1/game` 中间件）实测三次圆桌请求：**3/3 合法 scene**，耗时 **3856 / 3382 / 3562 ms**（证据 `.agent/tmp/review-r2-ui/after/real-model-calls.json`）。

在 800ms 预算下，真实调用**必然**在返回前被 abort 并回落 `manualPool`，等于“模型台词基本不出现”。这与演示主线「LLM 不可替代」及“评委三问”的证据诉求直接冲突。用户 2026-11-15 裁定按推荐方案 A 执行。

## 被选方案

1. `src/director/router.ts` 的 `roundtable.timeoutMs` 由 800 改为 **12000**；其余四档（1200/2000/600/0）不变。
2. `docs/design/HARNESS.md` §5 圆桌行预算同步改为 **12000 ms**，并注明依据本 ADR。
3. 中间件上游超时随 `routeTimeoutMs("roundtable")` 自动变为 12000ms，客户端与服务端口径继续共用同一常量。
4. 失败/超时行为不变：仍回落 `manualPool`，仍由 `voice_degraded` 叙事收编。
5. 同步两处契约测试（router 钉值、doc-alignment 表）。

## 修订：4000ms → 12000ms（同日）

首次只取了 3 个样本（3.4/3.6/3.9s）便定 4000ms，是取样不足。随后直连同一上游采样 6 次：
**3664 / 4012 / 4380 / 5742 / 6732 / 11060 ms**（p50≈5.7s，max≈11.1s）。
经中间件实测 6 次则 **全部在 4000ms 处被自身超时 abort（502）**——即 4000ms 会让多数真实调用失败，等于没解决问题。

故改为 **12000ms**：覆盖观测到的最大值并留出余量，同时仍有上界。这是修正先前的取样偏差，不是放宽标准。

## 被否方案及落选理由

- **保留 800ms（0019 原方案）**：落选——实测 3.5s+，演示中模型台词几乎不出现，主线证据链断裂。
- **保留 4000ms**：落选——6 次采样中 4 次超过 4s，实测 6/6 被 abort。
- **800ms + 一次 12000ms 重试**：落选——双倍延迟与额外预算消耗，且“首次失败”噪音大。
- **按端点延迟动态调整**：落选——引入随环境变化的变量进核心路径，与 0018 否决自迭代同一理由（不可复现）。

## 影响面

- `src/director/router.ts`、`docs/design/HARNESS.md`、`tests/director-router.test.ts`、`tests/director-doc-alignment.test.ts`。
- 0019 保持历史记录不改写，由本 ADR 明确取代其数值结论。
- 游戏内场景等待上限由 0.8s 变为 4s；若端点更慢，仍按 4000ms 回落。
