# 0022 — 结局锁定与 8/8 刻符解耦；闭包态不随世界存档持久化

日期: 2026-11-15

## 背景

0020 已把真·凝视的判据改为 `glyphsRead` 8/8 为唯一真源，并让零死亡周目也能解锁录音。但两个边界未写清：① 若 A/B/C 结局已入档并锁定，之后才凑齐 8/8，是否升级/重评？② `WorldState` 存档只序列化世界本体，`ontology/awakening/fxState/ledger` 等闭包态刷新即重置（0064 已登记为已知限制，但未作为产品口径正式确认）。

## 被选方案

1. **结局锁定优先**：`evaluateEnding` 对已有 `ending` 早退（现状），A/B/C 一旦入档即最终，8/8 之后到达**不改变**已锁结局、不重评。
2. **录音与结局解耦**：`recordingUnlocked`（8/8）独立于结局；已锁 A/B/C 的周目仍可播放真结局录音文本（作为“模型碰不到的文本”被发现），但塔与环境停留在已锁结局的终局表现，不切换到凝视终局。
3. **闭包态重置接受为演示范围**：刷新后 `ontology/awakening/fxState/ledger` 重置，`tick/gv/stage/creatures/memories/glyphsRead/ending` 逐字段一致（0064 验收）。这是最小存档面的可逆选择；完整闭包态持久化列为后续增强，不在本轮强改。

## 被否方案及落选理由

- **8/8 到达即覆盖已锁结局**：落选——违反“记录不可逆”的本体论；且会让已演出终局回退，破坏演示一致性。
- **为持久化闭包态扩张 WorldState**：落选——侵入 0065/0066/0068 写面，超本轮范围；先以文档口径确认已知限制，后续独立票评估。

## 影响面

- `docs/design/narrative/NARRATIVE-CORE-01`/`ART-CORE-03` 的结局表现阅读口径以本 ADR 为准；`src/sim/endings.ts` 行为不变（已是早退）。
- 测试：补“已锁结局后 8/8 不改 ending、录音仍解锁”断言（若尚未覆盖）。
- 不改 `canon.lock`、800 ms、N4 终局。
