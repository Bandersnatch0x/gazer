# 0016 — 演示就绪度采用分层口径(静态 / 综合)

日期:2026-11-14

## 背景

`EXECUTIVE_SUMMARY.md` 基于静态审查给出「有条件 PASS(静态口径)」;而 2026-11-13 的 B 组 Playwright 实机材料(`.agent/keep/ARCHIVE_20261113_GAZER-测试报告.md`)记录 6 条阻断级运行时缺陷 B1–B6(移动端顶部按钮条溢出、OSD 命中被盖、CRT 大分辨率裁切、真结局录音+NG+ 不可达、触屏 pointerId 泄漏冻结、瞳孔特写键盘陷阱)。两者不是同一命题:静态审查证明「源码接线 / 门禁 / 确定性 / 正典」,动态实测证明「实机视口几何、命中测试、键盘与触摸生命周期」。`REVIEW_CROSSCHECK.md` §4 S4 判定为范围口径冲突,须合并裁定。

## 被选方案

- **桌面 1280×800 + silent run / manualPool 兜底 + 不刷新 + 不进入 NG+/真结局录音链 + 不承诺实时 LLM 台词** → **有条件 PASS**,可用遮掩方案(`EXECUTIVE_SUMMARY.md:147-149`)。
- **综合口径(含移动 390×844 与 CRT 1920×1080 / 1440×900)** → **阻断**,须先修 B1/B2/B3/B6,并列 B5(触屏冻结)、B4(真结局录音 + NG+ 不可达)。
- 恒等禁令:「0 条 [阻断开发]」≠「0 阻断缺陷」;「模块等级 4」≠「实机交互可用」;静态结论不得覆盖或销账动态证据。
- 门禁事实单独硬说:`npm run check` exit 0 / 74 文件 / 1052 用例全绿、参赛切片 4/4、canon 与 FX 断言零漂移。

## 被否方案及落选理由

- **单一「PASS」**:落选——掩盖 4 条 `[R]` 实机复现的移动端/大分辨率阻断,对外口径不可证伪。
- **单一「FAIL」**:落选——否认门禁全绿、参赛切片交付与静态工程面健康,把范围口径冲突误判为全面失败。
- **把 B 组动态证据并入静态评分重算**:落选——方法不同,不存在可合并的单一分数(`REVIEW_CROSSCHECK.md` §7.1)。

## 影响面

- `EXECUTIVE_SUMMARY.md` §7、`REVIEW_CROSSCHECK.md` §4 S4 / §7.2。
- 票据优先级:T1(0063)、T2(0064)、T3(0065) 置顶;对外提交文案按分层口径书写。
- 不改 v3 权威文档;不新增里程碑百分比表述(见 0015)。
