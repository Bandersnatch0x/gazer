# 0002 — LLM 调用频率与时间倍率解耦:事件按游戏时间驱动、调用按真实时间配额节流

日期:2026-11-12

## 背景

v4 方案称「LLM 增量 ≈2 次/小时,在 v3.5 预算内」,按 ×1 速度计算(一游戏日 ≈ 2 小时真实时间)。但 `TimeFlowConfig` 提供 ×60 / ×1000 档:×60 下一游戏日 = 2 分钟真实时间,4–5 次/游戏日的调用立刻膨胀为 100+ 次/小时,远超 `docs/design/ARCHITECTURE.md` 的硬顶(15 次/30 分钟,超顶走 `llm:budget` 拒绝)。M8 验收「预算不超」在 ×60 下必然不成立。

## 被选方案

事件管道按**游戏时间**驱动,LLM 调用按**真实时间配额**发放;高倍速下事件排队合并:每真实 10 分钟最多放行 1 个 LLM 事件,其余降级为模板池。此节流规则写入 v4 规格文档。

## 被否方案及落选理由

- **倍速下暂停 LLM 事件(完全静默)**:落选——高倍速挂机正是观察世界的窗口,全部静默等于砍掉 ×60 档的演出价值;模板池降级保留演出,符合 Silent Run 降级血统。
- **按游戏日配额(每游戏日固定 N 次)**:落选——配额单位仍随倍率缩放,×1000 下等价于无上限,问题原样存在。

## 影响面

- v4 规格(`research/gazer-v4-shell`);`src/bridge/budget.ts` 的配额语义(真实时间单位不变,新增事件节流层);事件管道的队列与合并逻辑。
- 不改变既有 15 次/30 分钟硬顶。
