# 0024 — 越阶在正典序列完成后豁免静默配额（给模型一条玩家可达的说话路径）

日期: 2026-11-15

## 背景

0087 实机取证：`speakScene` 是唯一调用圆桌的入口，只由 `onStageChange` 触发；而 0→4 的每一次越阶都被正典门吃掉（E3 首次 GV≥40 替换、E4–E7 同 tick 主秀、E7 静默配额 250 ticks）。fetch 级探针显示整轮越阶 **0 次 fetch**，即模型台词在一整局内不可达。用户 2026-11-15 选 D：保留正典优先，但在正典序列结束后让每次越阶仍有 1 次模型场景，并写清触发条件。

## 被选方案

1. `src/game.ts` 的 `speakScene`：静默配额继续拦普通主动发言；**`stage crossed` 触发豁免配额**——越阶是事件驱动的场景请求，不是闲聊。
2. 其余四道门不变：`silent`、午夜静默、E3 替换、同 tick 正典主秀（`canonJustOwned`）。因此正典第一次爬升仍完整归正典所有（E3/E4–E7 各自吞掉对应的那次越阶）。
3. 模型调用仍受 4000ms 预算（0023）、`llm:budget` 硬预算与既有校验/回退约束。

实测依据（`.agent/tmp/review-r2-ui/speech-state.mjs`）：正典爬到 GV80 时 `fired=[E1,E3,E4,E5,E6,E7]`、`silenceUntilTick=258`，E2 因“5 次点击”条件未触发；若按“七件套全触发才放行”，普通玩家几乎永远等不到模型台词，故改为按触发类型豁免。

## 被否方案及落选理由

- **完全移除静默配额**：落选——E7 的静默是正典演出的一部分，移除会改写七件套语义。
- **要求七件套全部触发后才豁免**：落选——E2 依赖 5 次点击，普通路径下不触发，实测就等不到模型台词（等于没解决问题）。
- **新增玩家手势入口（长凝视触发圆桌）**：落选——范围更大，先用既有越阶路径；需要时另立票。
- **只等配额自然过期（250 ticks）**：落选——演示前仍有一大段无模型台词。

## 影响面

- `src/sim/awakening.ts`、`src/game.ts`、`tests/awakening.test.ts`（新 helper 单测）。
- 不改 canon 文本、不改 E1–E7 台词、不改 0023 的 4000ms、不改正典优先级。
- 已知边界：若玩家始终不让 GV 回落后再越阶，正典爬升期间仍无模型台词——这是正典优先的既定取舍，已在文档写明。
