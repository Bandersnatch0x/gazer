# 0017 — 三组评审的效力边界与证据等级

日期:2026-11-14

## 背景

本仓同时存在三组评审材料:A 组(2026-11/12 静态文档/代码/追溯/游戏视角四份)、B 组(2026-11-13 Playwright 动态实测 + 两路静态源码审查四份)、C 组(2026-11-13/14 校准版 v2 四份)。旧报告结论曾被当作全维结论使用;B 组内部还存在 `logic-audit.md:8-33`「门禁 0/0 未执行(spawn EPERM)」与 `GAZER-测试报告.md:21`「74 文件 / 1052 用例 / exit 0」的矛盾。

## 被选方案

- 三组**互补不互相覆盖**:静态文档/代码审查不能证伪浏览器动态缺陷;动态实测不能替代源码接线与门禁结论;跨组冲突逐条裁定入 `REVIEW_CROSSCHECK.md` §4。
- 门禁以 **② 校准版 `CODE_AUDIT.md:13` 真实执行 exit 0 / 74 文件 / 1052 用例** 与 B 组主报告更正为准;EPERM 0/0 记录属会话级沙箱环境差异,非代码失败,登记但不作为结论。
- C 组静态报告只登记 B 组运行时证据的**存在性与来源路径**,不得把 B1–B6 / D-1…D-7 判为「已销账」;静态效力边界(视口几何、`elementFromPoint`、z-index、键盘焦点、`pointerId` 生命周期、`touch-action`、音频听感、SW 离线、LLM 联机)必须在报告中显式声明。
- 既有评审原件与只读副本全部保留(`.agent/keep/REVIEW_ARCHIVE_INDEX.md`),不覆盖、不删除。

## 被否方案及落选理由

- **用静态「有条件 PASS」覆盖 B 组运行时阻断**:落选——方法不可互相证伪(0016)。
- **把 EPERM 0/0 当作代码失败并回滚门禁结论**:落选——主报告已复跑并更正,② 亦在同一 HEAD 实测通过。
- **删旧版报告腾空间**:落选——用户明确要求保留既有评审做交叉对比;Δ 对比节依赖其全文。

## 影响面

- `REVIEW_CROSSCHECK.md` 全篇;`.agent/keep/REVIEW_ARCHIVE_INDEX.md`;五份校准版报告的「输入清单 / Δ 对比 / 效力边界」节。
- 0063(T1)票必须把 B1–B6 / D-1…D-7 的截图与命中测试证据作为验收输入。
- 验收(阶段 7)按「静态门禁 + 动态证据」双轨登记,不以单轨宣称完成。
